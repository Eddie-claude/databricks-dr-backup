# v4.3 — Factorisation des E/S ADLS et logs loguru — Design

Date : 2026-10-07 — Statut : validé en conversation, en attente de relecture du plan

## Contexte

- Les helpers `_uc_head` (11 copies), `_uc_put` (4 copies, déjà divergentes), `_uc_read_binary` (1)
  et `_short` (7 copies) sont recopiés dans les notebooks. Le bug de lecture ADLS de juillet a coûté
  deux commits (`5efe21b` puis `55dcf84`) faute de point unique de correction.
- Le code contient ~770 `print` (~540 hors `demo/`), avec une convention manuelle de niveaux
  (`[OK]`, `[INFO]`, `[WARN]`, `[ERROR]`, `[SKIP]`, `[AUTO]`, `[RESUME]`).
- Le client utilise loguru sur ses autres repos, installé comme bibliothèque de tâche PyPI à version
  fixée (comme `jinja2==3.1.6`), dernière version (0.7.3 au 2026-10-07), avec cette configuration :

```python
def create_logger(level = "INFO"):
    logger.remove()
    logger.add(sys.stderr, level=level, colorize=True,
               format="<cyan>{time:YYYY-MM-DD HH:mm:ss}</cyan> | <level>{level:<8}</level> | <green>{name}</green> | <blue>{function}</blue>:<yellow>{line}</yellow> | {message}")
    return logger
```

## Constat bloquant découvert le 2026-10-07 (lecture seule, workspace KeyIT)

Les jobs passent `lib_path = /Workspace/Shared/dr-backup/lib` (variable `lib_path` de `databricks.yml`).
Ce dossier est une **copie manuelle ancienne** : il ne contient que `__init__.py`, `diff.py`,
`report.py`, `templates/`. Le bundle, lui, déploie le `lib/` complet dans
`${workspace.file_path}/lib` (`/Workspace/Shared/dr-backup/.bundle/dr-backup/prod/files/lib`),
que personne n'utilise. Le dossier `lib_path` de la cible dev n'existe pas.

Conséquences actuelles sur KeyIT : `01_uc_metadata` saute l'export volumes/fonctions (ImportError
`uc_ddl` rattrapée, simple WARN), `14_volume_files` échoue (non critique), et les restaurations
08/09/12/13/15 lancées avec la valeur par défaut du widget échouent sur ImportError. Déplacer
`_uc_put` dans `lib/` sans corriger cela ferait échouer `02_data_clone`, donc tout le daily.

## Décisions

1. **lib_path suit le bundle.** Les jobs passent `${workspace.file_path}/lib`. La valeur par défaut du
   widget `lib_path` est calculée depuis le chemin du notebook (`…/notebooks/x` → `…/lib`), ce qui
   couvre les lancements manuels. La variable `lib_path` disparaît de `databricks.yml`. La CI
   synchronise aussi `lib/` à côté de la copie directe des notebooks.
2. **`lib/uc_io.py`** : classe `UcIO(spark, dbutils)` (injection, aucun global, aucun effet à l'import)
   avec `head(path)`, `put(path, content)`, `read_text(path)`. Comportement identique à l'existant ;
   le paramètre `overwrite` de `_uc_put` (jamais utilisé par un appelant) est supprimé.
3. **`lib/logger.py`** : `create_logger(level="INFO")` reprend **à l'identique** la configuration du
   client (stderr, couleurs, format). Si loguru est absent (restauration lancée à la main sur un
   cluster sans la bibliothèque, script local), repli sur `logging` avec le même format sans couleurs
   et la même API (`debug/info/success/warning/error/exception`). Contient aussi `short_error(e, limit)`.
4. **Installation** : `libraries: - pypi: {package: loguru==0.7.3}` sur les tâches des jobs qui
   exécutent du code converti (daily, monthly, grants_sync) ; `loguru==0.7.3` dans `requirements.txt`.
5. **Conversion** : appels en f-string sans argument positionnel (loguru ne formate pas un message sans
   arguments : les `{}` des données — JSON, DDL — sont sans danger). `[OK]`→`success`,
   `[INFO]`→`info`, `[WARN]`→`warning`, `[ERROR]`/`✗`→`error`, `[SKIP]`/`[AUTO]`/`[RESUME]`→`info`
   en gardant l'étiquette. Les blocs de restitution (récapitulatifs multi-lignes, plans de dry-run)
   restent des `print`. Pas de `logger.exception` sur les erreurs Spark (stacktrace JVM de centaines de
   lignes → sortie de notebook tronquée) : `logger.error(f"... {short_error(e)}")`.
6. **Périmètre** : notebooks livrés et `scripts/restore_*.py`. Hors périmètre : `notebooks/demo/`,
   `diag_*` (outils de pré-déploiement sans `lib/`), `scripts/export_workspace.py` (CI interne KeyIT),
   `docs/generate_*.py`. **`07_restore` et `11_restore_grants` restent autonomes** (aucune dépendance
   à `lib/` aujourd'hui) : chemins de restauration de dernier recours.
7. **Livraison** : un `bundle deploy` atomique, validation sur dev avant tout push (chaque push redéploie
   KeyIT via GitHub Actions).
